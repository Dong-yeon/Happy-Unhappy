# 사람 플레이 테스트 계획 (M7 이후)

> 프로토타입 스펙 §1 가설 H1~H6와 재미 판정 기준을 사람 플레이로 확인한다. 봇 결과(§8.2)는 밸런스 기준선일 뿐 재미를 판정하지 못한다 (D-020).
> 결정 근거: `docs/03-decisions/decision-log.md` D-025

## 왜 두 트랙인가
C안 gating(하루 2일 지급)에서는 **한 일생(14일) = 실제 7일**이다. 그리드 3종을 각각 정상 진행으로 한 번씩 하면 3주가 걸려 타임박스(2~4주)를 거의 다 쓴다. 그래서 목적을 나눈다.

| 트랙 | 목적 | 설정 | 기간 |
|---|---|---|---|
| **A. 실제 일생** | H4(다음 날이 기다려지는가), 결말 납득, 역류 체감, 그림일기 | `?playtest=1`, 5×4, **gating 정상** (우회 금지), 배속 ×1 | 실제 7일 (하루 2판) |
| **B. 그리드 비교** | H6·D-012 (그리드 막힘이 전략인가 짜증인가), H1·H2 | `?debug=1`, 4×4 / 6×4 각 1회, gating 우회, **1~5일차만**, 배속 ×1 | 트랙 A와 병행, 프리셋당 1~2시간 |

- 트랙 B는 우회일로 기록되어(`bypass`) H4 분석에서 자동 제외된다.
- 트랙 A 도중에는 디버그 조작을 하지 않는다 (했으면 메모에 남김).

## 준비
1. PC에서 `npm run dev` 실행 (이미 `--host`), 폰에서 같은 와이파이로 접속 (`http://<PC IP>:5173/?playtest=1`).
2. 폰 홈 화면에 바로가기 추가 (매일 켜기 쉽게).
3. 첫 실행 전 디버그 "저장 초기화: 전부" + "metrics 초기화".

## 매일 (트랙 A)
- [ ] 하루 2판 (열 수 있는 날만큼). 그림일기 뒤 평가 버튼 누르기
- [ ] 판이 끝나고 한 줄 메모 (아래 표)
- [ ] 이틀에 한 번 metrics JSON 내보내기 → `playtest/` 폴더에 날짜별 저장

| 날짜 | 일차 | 오늘 가장 기억나는 순간 | 고민한 선택이 있었나 (위/아래, 보낼까/합칠까) | 짜증난 순간 |
|---|---|---|---|---|
| | | | | |

## 트랙 B (프리셋마다)
- [ ] 4×4로 1~5일차 → metrics 내보내기 → 메모
- [ ] 6×4로 1~5일차 → metrics 내보내기 → 메모
- 메모: 그리드가 막힌 순간이 있었나 / 막혔을 때 "어떻게 풀지"를 고민했나, "짜증"이었나 / 5×4와 비교한 느낌

## 끝나고 판정 (§1 재미 판정 기준)
| 기준 | 근거 | 판정 |
|---|---|---|
| 3일 이상 연속으로 스스로 켜게 되는가 | metrics 세션 날짜 + 메모 | |
| Unhappy에게 보내는 것이 "투자"로 느껴지는가 | H1·H3 + 메모 | |
| 역류가 짜증이 아니라 긴장감인가 | 역류 평가 긴장/짜증 비율 | |
| 그림일기를 읽게 되는가 | 메모 | |
| 결말이 납득되는가 | 결말 납득 [응]/[아니] + 두 점수 | |

**함께 정할 것 (데이터가 나오면):** 그리드 크기(D-012), 하루 길이 목표(3~5분 유지 or 수정), `dailyLimit`·`storeCap`, 결말 임계값 재보정(봇 기준 770 → 사람 기준).

분석: `npm run metrics -- playtest/<파일>.json --bot sim/out/<balanced 리포트>.json`
