## 2026-09-29

### D-001. 세계관: 한 사람의 마음, 양(의식)과 음(무의식) 두 세계
- **결정:** 무대는 한 사람의 마음속. 핵심 규칙은 "불행을 외면하면 역류한다".
- **이유:** 행복/불행 개념을 공간 구조(수면 위/아래)로 표현할 수 있고, 억압→역류가 시스템과 메시지를 동시에 만든다.

### D-002. 아트·플랫폼: 도트(픽셀) 그래픽, 모바일
- **이유:** 팔레트 스왑으로 양/음 에셋을 재사용할 수 있어 1인 개발 비용이 낮다.

### D-003. 개발 전략: Phaser 3 프로토타입(버리는 코드) → Godot 4.7 본 개발
- **이유:** 프로토타입은 빠른 검증이 목적. 본 개발은 네이티브 실행(배터리·발열·저사양 안정성)이 유리.
- **이관 대상:** 코드가 아니라 규칙 문서 + JSON 수치.

### D-004. 톤: 동화 톤의 따뜻한 게임
- **결정:** 불행은 무섭게 그리지 않고 "안아줄 존재"로. 긴장감은 공포가 아니라 쓸쓸함으로.
- **버린 대안:** 씁쓸한 성장물.

### D-005. 마음의 주인: 한 아이 / 플레이어는 Happy·Unhappy를 키운다
- **결정:** 아이는 직접 조작하는 용사가 아니다. Happy·Unhappy를 어떻게 키웠느냐에 따라 아이가 어떤 어른이 되는지 결정된다.
- **버린 대안:** 플레이어 자신(구체적 기억을 쓰기 어려움), 반려동물(억압/가면 등 사람 심리 기반 규칙이 성립하지 않음), 아이 = 용사(시점 혼란).

### D-006. 결말: 2×2 + 히든 (Happy·Unhappy 성장 균형으로 판정)
- 웃는 가면 / 조용한 어른 / 비 오는 어른 / 단단한 어른 / (히든) 화해
- 분기는 트리가 아니라 누적 변수.

### D-007. 코어 판타지
- "Happy는 행복을 방해하는 공격을 막고, Unhappy는 심연으로 내려가 불행을 정화한다. 둘이 합쳐질 때 아이는 비로소 행복해진다."
- **표현 원칙:** "부순다"가 아니라 "정화한다". 불행을 없애는 것이 아니라 되돌려 놓는 것.

### D-008. 타이틀 연출: 수면 반사 로고 + 결말별 엔딩 제목
- **이유:** Unhappy 안에 Happy가 들어 있다는 말장난으로 반전을 설명 없이 전달.
- **주의:** 영어에서만 성립 → 로고는 영어 유지, 반전은 시각 연출.

### D-009. 1인 개발 전제에서 장르 구조 재검토
- **검토한 안**
  | 안 | 구성 | 판단 |
  |---|---|---|
  | A | 머지 디펜스(수동) + 방치형 음 | 게임성은 강하나 1인 개발 비용·리스크 최대 |
  | B | 둘 다 방치형 | 비용 최저, 정체성 약함 |
  | C | 방치형 머지 + 방치 | 균형형 |
  | D | 디펜스 + 오펜스 둘 다 수동 | 조작 체계 2벌, 콘텐츠 제작비 최대, 완결형 게임에 적합 |
- **결론:** D-010으로 대체.
- **개발 방식:** 양/음을 따로 완성 후 합치지 않는다. 코드는 모듈 분리, 개발은 항상 연결된 얇은 버전으로.

### D-010. 핵심 조작: 머지 그리드 하나 + 소환 통로 두 곳
- **결정:** 플레이어는 머지 그리드만 조작. 합친 조각을 위(양 방어 레인) 또는 아래(음 심연 레인)로 보내 소환. 전투는 양쪽 자동.
- **이유:** 조작 체계 1개로 두 세계를 모두 구현. "위로 보낼까 아래로 보낼까"라는 한 번의 선택이 게임의 역설(음을 외면)을 표현. 레인 전투 코드는 방향만 뒤집어 공유.
- **설계 원칙:** 위 = 즉시 효과, 아래 = 지연되지만 더 큰 보상.
- **버린 대안:** 음 = 머지 오펜스(양과 동작 중복, 역설 약화), 음 = 기억 덱 편성(스톤에이지 키우기식, 로스터 비용 과다 → 본 개발 장기 레이어로 보류).

### D-011. 추억 체인과 영웅 소환
- **결정:** 조각에 종류(추억 체인)와 단계가 있다. 체인의 3단계 = 고유 영웅 (예: 강아지 발자국 → 공놀이한 오후 → 강아지 영웅). 1~2단계는 공용 유닛.
- **이유:** 수집 동기를 머지 안으로 흡수. 아트 비용을 영웅에만 집중.
- **리스크 대응:** 그리드 막힘(그리드 확대, 챕터당 체인 2~3개, 와일드카드, 놓아주기), 영웅 수 제한(챕터당 3~4명, 전체 15~20명), 이별 소재는 상징적으로만.

### D-012. 그리드 크기: 프로토타입에서 3안 비교 후 결정
- **결정:** 그리드 크기는 `balance.json`의 파라미터(`gridCols`, `gridRows`)로 두고, 프로토타입에서 **4×4(16칸) / 5×4(20칸) / 6×4(24칸)**을 비교한다.
- **이유:** 우리 그리드는 전장이 아니라 **대기실**이다(보낸 조각은 그리드를 떠남). 너무 넓으면 쌓아두기만 해도 되어 "지금 보낼까, 더 합칠까" 긴장과 아래로 보낼 압박이 약해진다. 너무 좁으면 추억 체인 때문에 금방 막힌다.
- **상한:** 세로 화면에 레인 2개 + 그리드가 함께 들어가야 하므로 터치 칸 크기 기준 6×4가 현실적 상한.
- **판정 지표 (metrics)**
  | 지표 | 너무 좁다는 신호 | 너무 넓다는 신호 |
  |---|---|---|
  | 그리드 가득 참 상태 시간 비율 | 높음 (막힘) | — |
  | "놓아주기" 사용 횟수 | 많음 | — |
  | 조각 생성 → 소환까지 평균 보유 시간 | — | 김 (쌓아두기) |
  | 소환 시 평균 단계 | — | 거의 항상 최고 단계 (쌓아서 한 번에) |
  | 아래로 보낸 비율 | — | 낮음 (압박 없음) |
- **참고:** 운빨존많겜 등 필드형 디펜스는 그리드 = 전장이라 넓은 그리드가 필요하지만, 우리 구조와는 그리드의 역할이 다르다.

### D-013. 소환 후 레인 규칙: 위는 소모, 아래는 성장해서 귀환
- **결정**
  - 위(방어 레인): 방어선에 정지, 체력제 소모형. 걱정 처치 시 즉시 기쁨.
  - 아래(심연 레인): Unhappy 뒤에서 전진, 체력제. 층 돌파 시 정화 → **단계 +1로 그리드 귀환**. 쓰러지면 조각 소실 + 그림자 증가.
  - 레인 정원: 프로토타입 각 5기 (JSON).
  - 3단계 영웅 정화 성공: 와일드카드 1개 + 추억 도감 진척.
  - Happy: 쓰러지지 않는 방어 거점. Unhappy: 아래로 보낸 추억 없이는 전진 불가 → 멈추면 그림자 누적 (= 외면의 정의).
- **이유:** "지연되지만 더 큰 보상" 원칙을 구체 규칙화. 위=확실·즉시·소모 / 아래=느림·위험·성장 으로 선택에 실제 비용이 생긴다.
- **퇴화 전략 방지:** 한쪽만 보내면 반대쪽 불이익이 누적되는 자기 균형 루프 (아래만 → 걱정 가라앉음 → 심연 강화 / 위만 → Unhappy 정지 → 역류).
- **버린 대안:** 영구 유닛(정원만 차고 선택 압박 소멸), 시간제 유닛(체감이 약하고 전투 결과와 무관).

### D-014. 게임 구조: 하루 = 한 판, 끝이 있는 일생
- **결정:** 매일 아이의 하루를 한 판(아침·낮·저녁 3웨이브, 3~5분)으로 산다. 그날의 이벤트가 그리드에 들어오는 조각과 몰려오는 걱정을 결정한다. 하루 끝에 그림일기 한 줄이 일기장(추억 도감)에 쌓인다. 어른이 되면 결말.
- **이벤트 체계:** 이정표(고정, Happy/Unhappy 선택은 여기서만) / 계절(매년 반복) / 일상(랜덤) / 평범한 하루.
- **이유:** "평범한 하루도 소중하다"는 메시지를 구조로 전달. 매일 접속 동기(F2P 장점)와 끝이 있는 이야기(완결형 장점)를 동시에 확보. 회차 길이 문제를 "일생의 날 수"로 해결.
- **제품 목표 결론:** "매일 하루를 사는 완결형 일생 게임" (F2P vs 완결형 논의 종료). 오프라인 방치 진행은 하지 않는다.
- **콘텐츠 비용 대응:** 하루 = 템플릿 + 이벤트 풀 조합. 이정표만 수작업.
- **규모 목표값:** 일생 약 120일, 이정표 15개 안팎, 계절 8~10종, 일상 풀 30~40개 (확정 아님).

### D-015. 하루 진행 방식: C안 (일일 제한 + 밀린 날 보관)
- **결정:** 하루에 열 수 있는 날 수를 제한하고, 밀린 날은 일정 일수까지 보관한다. 보관 한도를 넘은 날은 벌칙 없이 "기억나지 않는 날"로 지나간다.
- **이유:** 매일 접속할 이유 + 몰아하기 일부 허용. 벌칙이 없어 따뜻한 톤 유지.
- **버린 대안:** A. 실제 하루 = 게임 하루(몰아하기 플레이어 이탈), B. 판마다 하루 경과(매일 접속 동기 약함).
- **미정:** 일일 제한 날 수, 보관 한도 (프로토타입 후 결정).

### D-016. 아이의 배경(세계): 출시는 1개, 원형 + 스킨 구조로 확장
- **결정:** 아이가 태어나는 세계를 여러 개 두되, 1.0은 **동화풍 현대 1개**. 규칙·체인·이벤트 뼈대는 원형(archetype)으로 공유하고, 세계는 이름·텍스트·도트를 바꾸는 스킨으로 추가한다. 일생을 마치면 다음 세계가 열린다(회차).
- **이유:** 회차 동기·마케팅 포인트·업데이트 단위를 확보하면서, 세계 수만큼 곱해지는 콘텐츠 비용을 스킨 팩 수준으로 통제.
- **난이도 원칙:** 세계별 난이도는 가상 세계의 설정에서만. 실제 역사·국가 배경에는 난이도 차등을 두지 않는다 (문화 고정관념 리스크).
- **확장 순서:** 가상 세계(판타지, SF 등) 먼저 → 실제 역사 배경은 조사·표현 검토 후. 공룡(비인간)은 의인화 조건부 후순위.
- **버린 대안:** 출시 시 다수 세계 동시 제공 (1인 개발 콘텐츠 비용 과다).
- **데이터 영향:** 콘텐츠 JSON에 `world` 필드, `archetypeId` + `skins.{worldId}` 구조. 프로토타입은 세계 1개만 구현.

### D-017. 화면 구조: 가운데 거울을 경계로 좌우 분할, 그리드는 하단
- **결정:** 왼쪽 = 방어 레인(양, Happy), 가운데 세로 **거울**, 오른쪽 = 심연 레인(음, Unhappy), 하단 = 머지 그리드. "위로/아래로 보내기" → "Happy에게/Unhappy에게 보내기". 드롭 판정은 레인 영역 전체.
- **이유:** 그리드가 엄지 영역(하단)에 오고, 두 레인이 세로로 길어져 전투를 읽기 쉽다. 두 세계를 나란히 비교할 수 있다. 거울은 원래 좌우를 반전해 비추므로 "Happy와 Unhappy는 같은 사람의 두 면"을 수면보다 직접적으로 표현한다.
- **반전 구조 유지:** 두 레인 모두 거점은 그리드 쪽(아래). 왼쪽은 걱정이 다가오고, 오른쪽은 추억이 멀어져 거울 속으로 들어간다 (그림자 벽은 오른쪽 레인 위쪽 끝). 레인 전투 코드 공유 유지.
- **리스크:** 조각의 칸 위치(왼쪽/오른쪽 열)에 따른 선택 편향, 오른손잡이 편향 → metrics에 소환 시 칸 위치·드롭 실패 기록.
- **파급:** 타이틀 로고 수면 반사 → 거울 반사. "심연으로 내려간다" → "거울 속 깊이 들어간다". 스펙 v0.3, `balance.lane.defenseLineY` 삭제(화면 좌표는 layout.ts에만).
- **버린 대안:** 수면 위/아래 분할(세계관은 강하나 그리드가 화면 중간이라 한 손 조작 불리), 좌우 분할 + 의미 없는 경계, 펼친 그림일기 책(그림일기와 연결되나 "같은 사람의 반전" 의미가 약함), 레인 위아래 + 그리드 최하단(심연이 그리드에 가까워 선택 편향).

### D-018. 포탈 소환과 연결감: 그리드와 두 세계를 한 판으로 잇는다
- **결정**
  - 거울 받침 가운데에 포탈 2개를 나란히: ☀ 창문(Happy에게) / ◐ 손거울(Unhappy에게). 그리드 밖, 레인 바닥과 그리드 윗변에 반쯤 걸쳐 배치.
  - 조각을 포탈로 드래그해 소환. **판정은 넓게**(포탈 주변 또는 해당 레인 전체), **연출은 항상 포탈 경유**.
  - Happy는 창문 포탈 위, Unhappy는 손거울 포탈 위에 선다 (각자의 문 앞).
  - 레인 정원이 차면 포탈이 닫힌 모습.
  - **흐름 연출**: 소환(조각 → 포탈 → 레인), 기쁨(처치 → 창문 → HUD), 귀환(층 돌파 → 손거울 → 그리드), 가라앉음(방어선 → 거울 → 그림자 벽). core는 즉시 상태 변경, scene은 뒤따라 연출.
- **이유:** 어디로 보내는지 직관적이고 귀엽다. 보내는 순간이 보상 순간이 된다. 그리드와 두 세계가 따로 노는 느낌 대신 "값이 포탈과 거울을 통해 오가는 하나의 마음"으로 보인다.
- **편향 대응:** 포탈을 그리드 양 끝이 아니라 가운데에 두어 칸 위치별 거리 차이를 줄인다. 그리드는 중립 색 (좌우를 양/음 색으로 칠하지 않음).
- **버린 대안:** 포탈을 그리드 양 끝에 배치(칸 위치 편향), 포탈을 그리드 칸으로 사용(칸 수 감소·위치 고정), 작은 포탈만 판정(드롭 실패 증가).

### D-019. 놓아주기는 드래그로, 귀환 조각은 난수 칸에
- **결정:** 놓아주기 모드(버튼으로 켜고 탭)를 없애고, 하단 바의 놓아주기 영역으로 조각을 드래그한다. 올리면 환급액 미리보기, 와일드카드는 비활성 표시. 심연에서 돌아온 조각은 rng로 고른 빈 칸에 배치한다.
- **이유:** 모든 조작(머지·소환·놓아주기)을 드래그 하나로 통일. 모드를 켜둔 채 잊어 생기는 실수와 "모드 중 드래그 불가" 문제가 사라진다. 영역이 그리드 아래라 위쪽 포탈과 멀어 오조작이 적다. 귀환 조각을 첫 빈 칸(왼쪽 위 = 창문 포탈 근처)에 두면 Happy 쪽 소환 편향이 생겨 H1 측정이 흐려진다.
- **버린 대안:** 놓아주기 모드 유지(M2 구현본), 확인 창(흐름을 끊음 → 미리보기로 대체), 귀환 조각을 손거울 포탈에 가장 가까운 칸에(Unhappy 쪽 편향).

### D-020. 난이도: 한 번에 최선의 결말이 나오지 않게 + 자동 플레이 시뮬레이터로 조정
- **결정**
  - 게임 오버는 없다. 난이도는 **결말의 질과 역류**로 표현한다.
  - 첫 일생에서 "단단한 어른"·히든은 쉽게 나오지 않는다. 회차(다음 세계)를 거치며 도달하는 목표.
  - 초반(1~2일차)은 쉽게, 이정표·역류가 긴장의 봉우리.
  - 한쪽만 고집하는 퇴화 전략은 최선의 결말에 도달하지 못한다.
  - 밸런스는 headless **자동 플레이 시뮬레이터**(봇 정책 idle / random / alwaysHappy / alwaysUnhappy / hoarder / balanced)로 조정하고, 사람 플레이로 보정한다. 수치 목표는 스펙 §8.2.
- **이유:** 대부분의 게임처럼 한 번에 최선의 결과가 나오면 회차 동기와 성취감이 사라진다. 게임 오버 대신 결말의 질로 표현하면 따뜻한 톤을 지키면서 난이도를 줄 수 있고, 다중 결말·회차 구조(D-006, D-016)와 맞물린다. core가 Phaser 비의존·결정적(고정 틱, 시드 rng)이라 수백 판을 빠르게 돌릴 수 있다.
- **주의:** 봇은 재미를 판정하지 못한다. 봇 리포트와 사람 metrics가 어긋나면 봇 정책을 고친다. 모바일 일일 플레이 특성상 초반 난이도가 높으면 이탈하므로 초반은 쉽게.
- **버린 대안:** 게임 오버/재도전 구조(따뜻한 톤과 충돌), 사람 플레이만으로 밸런스(1인 개발로 표본이 부족).

### D-021. 역류는 그날 안에서, 다음 날로 넘어가면 준비 시간
- **결정:** 역류가 예약되면 그날 남은 웨이브 칸 하나를 보스 웨이브로 **교체**한다(하루는 항상 3웨이브). 저녁 웨이브 도중·이후에 예약되면 다음 날 아침이 보스이고, 그 전에 **준비 시간(`bossPrepSeconds`, 기본 10초) + 경고**를 준다. 보스 HP는 일차에 따라 성장(`hpGrowthPerDay`).
- **이유:** M4 시뮬에서 `balanced`는 보스 HP를 350까지 낮춰도 처치 0회. 하루 끝 방어 유닛 해산 → 다음 날 첫 순간 보스 → 빈 방어선 통과가 유력한 원인. 역류는 "외면의 대가"여야지 "피할 수 없는 함정"이면 안 된다 (따뜻한 톤, D-020).
- **검증:** M5에서 보스 등장 시점의 방어 상태를 기록해 원인을 데이터로 확인. 준비 시간이 있는 아침 보스 처치율 ≥ 50%가 목표 (0%면 구조 재검토).
- **버린 대안:** M4식 끼워 넣기(하루 길이가 들쭉날쭉), 역류가 있으면 방어 유닛을 해산하지 않기(하루 끝 규칙이 복잡해짐).

### D-022. 하루 끝에 방어 유닛도 그리드로 귀환 (해산 폐지)
- **결정:** 하루 끝에 방어 레인의 살아남은 유닛은 **단계 그대로 그리드로 귀환**한다 (심연 유닛과 같은 규칙). 방어선에 남은 걱정은 사라진다. `unhappyStallShadowPerSec` 0.3 복원.
- **이유 (M5 시뮬, 14일 × 시드 200):** 매일 해산 → 매일 방어 재구매 → 기쁨은 처치로만 들어오므로 "못 막음 → 기쁨 감소 → 더 못 막음" 악순환. balanced 기쁨 4일차부터 0, 보스 등장 시 방어 0기가 90%(2628회 중 2372회), 보스 처치 0회, 목표 5/12. 귀환으로 바꾼 실험: 가라앉음 269 → 0, 층 돌파 2 → 21, Unhappy 비율 11% → 57%, 3단계 소환 3% → 55%, 목표 11/12. 세계관 표현: "하루가 끝나면 추억들은 그리드로 돌아와 쉰다."
- **대가:** 난이도가 크게 낮아짐 (balanced 무가라앉음). 걱정 성장률 등 수치로 M6 결말 분포(D-020)에 맞춰 올린다.
- **D-013 수정:** "위는 소모" → "위는 쓰러지면 사라지고 살아남으면 그대로 돌아온다(성장 없음)". 위/아래의 비대칭(즉시·확실 vs 지연·성장)은 유지.
- **버린 대안:** 매일 기본 기쁨 지급만 추가(+30 실험: 가라앉음 136, 층 7.5로 부분 개선에 그침), 해산 유지 + 보스 준비 시간만(D-021 단독으로는 처치율 0%).

### D-023. 결말 판정 보정 + 하루 경계 저장 (M6)
- **결정**
  1. 결말 점수의 `shadowPurified`는 **층 돌파로 줄인 그림자만** 센다. 역류 보스 승리로 줄어든 그림자는 `shadowCalmed`로 따로 기록하고 점수에 넣지 않는다.
  2. 결말 임계값을 `thresholds.happy` / `thresholds.unhappy`로 분리 (초기값 둘 다 100 = 기존 동작).
  3. 히든 결말의 균형 조건을 절대값(`balanceGap` 20)에서 비율(`balanceRatio` 0.15 × 큰 쪽 점수)로.
  4. C안의 하루 소비는 **하루를 끝낼 때**. 게임 저장은 **하루 경계(dayStart·diary·lifeEnd)에서만** 하고, 판 도중 종료는 그날 시작으로 복원.
  5. M6(구현)과 M6.5(결말 분포 튜닝)를 분리.
- **이유 (M6 직전 시뮬, 시드 100, 현재 가중치):**
  1. `alwaysHappy`의 unhappy 점수 60이 **전부 보스 승리분**. Unhappy를 외면해 생긴 역류를 Happy가 막은 것이 Unhappy 점수가 되면 역설(D-001)이 뒤집힌다.
  2. 점수 규모가 다르다 (balanced 중앙값 happy 741 / unhappy 969, alwaysUnhappy unhappy 80). 하나의 T로는 한쪽을 맞추면 다른 쪽이 어긋난다.
  3. 점수가 수백 단위라 ±20은 사실상 운. 비율이어야 튜닝으로 히든 5~15%를 겨냥할 수 있다.
  4. 웨이브 도중 상태 저장은 레인·걱정·타이머 직렬화가 필요해 비용이 크고, 하루 단위 게임이라 잃는 것이 한 판뿐. 하루 끝에 소비하면 도중 종료 시 "날은 썼는데 진행은 없음" 문제가 생기지 않는다.
  5. 튜닝 전 기준선이 있어야 `--compare`로 전후를 비교할 수 있다.
- **대가·한계:** 판 도중 종료로 나쁜 하루를 되감을 수 있다 (따뜻한 톤상 허용, M7 metrics `midDayRestores`로 관찰). 기기 날짜를 앞으로 돌리는 치트는 막지 않는다.
- **관찰 (M6.5 과제):** 점수가 "보낸 양"(`sentUpTierSum`·`sentDownTierSum`)에 지배된다 (balanced unhappy 969 중 732). 결과 항목(처치·층 돌파) 비중 재검토.
- **버린 대안:** 웨이브 중 전체 상태 저장(비용 대비 이득 적음), 하루 시작 시 소비(도중 종료 시 손해), 보스 승리분을 Happy 점수로 이동(막은 것은 이미 `worriesDefeated`로 반영됨).

### D-024. 소프트락 방지 + 결말에 "지키지 못한 것" 반영 (M6.5)
- **결정**
  1. **조용한 날:** 1~2일차는 고정 이벤트 외에 일상 이벤트가 없다 (`days.quietDays` 2).
  2. **아침 기쁨 바닥:** 하루 시작(이벤트 효과 직후) 기쁨이 `morningJoyFloor`(20) 미만이면 20으로. 가산이 아니라 바닥.
  3. **Happy 점수에 가라앉음 감점** (`wSunk` 2), 두 점수는 0 하한. `wJoy` 0.
  4. 걱정 성장 `hpGrowthPerDay` 1.08 → 1.13, `countStep` 1 → 2. 결말 가중치·임계값·균형 비율 재설정 (스펙 §5.9-4).
  5. §8.2: hoarder 비교를 결말 점수로, M5 아침 보스 목표를 "방어 ≥ 3기" 조건부·전 정책 합산으로.
- **이유 (M6 시뮬):**
  1·2. `balanced` 비 오는 어른 7%는 전부 1일차 `scraped_knee`(걱정 ×1.4) → 1~2일차 35마리 가라앉음 → 기쁨 0 + 빈 그리드 → 14일 내내 생성 불가인 **소프트락**. 실력이 아니라 운이고, 사람도 빠질 수 있다. 조용한 날만으로 `balanced` 무가라앉음 89% → 100%. 바닥은 사람용 안전망 (봇 `hoarder`의 초반 붕괴 회복도 확인).
  3. 감점이 없으면 Happy 점수는 "보낸 양"만 재고, 결말이 임계값 위치로만 갈린다. 감점을 넣으면 "아래는 뚫었지만 위를 지키지 못한 판 → 조용한 어른"이 되어 결말이 플레이의 질을 반영한다.
  4. 결과 (시드 200): balanced 단단한 35.5% / 히든 13.5% / 조용한 50%, alwaysHappy 웃는 가면 100%, alwaysUnhappy·random·idle 최선 0%, hoarder 점수 합 731 < balanced 1535. M6 목표 전부 충족.
  5. 난이도를 올리면 balanced가 아래 투자로 가라앉음이 생겨 "가라앉은 수"로는 쌓아두기 지배 여부를 못 잰다. 준비된 아침 보스는 balanced에서 무너진 판에만 나와(방어 1기·기쁨 10) 표본이 편향됐고, alwaysHappy는 341/341 처치 → D-021 구조는 작동.
- **대가·한계:** `hpGrowthPerDay` 1.12 ↔ 1.14에서 balanced 단단한 어른 51% ↔ 18%로 민감. 임계값 770은 걱정 수에 묶인 절대값 → 웨이브 구성을 바꾸면 재보정. 봇 기준이므로 M7 사람 플레이로 다시 맞춘다.
- **버린 대안:** 임계값만 올리기(기준선 옮기기), 매일 기쁨 가산(D-022에서 기각), 결말 공식 비율화(처치율 등 — 더 견고하지만 프로토타입 범위 초과, 본 개발 검토 대상), 봇이 보스 중 창문 우선(실험 결과 변화 없음).

### D-025. 사람 플레이 테스트를 두 트랙으로 + 주관 평가를 게임 안에서 기록
- **결정:** (A) 5×4·gating 정상·우회 금지로 실제 일생 1회, (B) 4×4·6×4는 gating 우회로 1~5일차만. 하루 끝·역류·결말에 버튼 하나짜리 주관 평가를 `?playtest=1`/`?debug=1`에서 기록한다. metrics는 저장과 분리된 키(`hau_metrics_v2`)에 로컬로만 남기고 JSON으로 내보낸다.

- **대가:** 그리드 비교는 1~5일차 표본뿐 (후반 그리드 압박은 트랙 A의 5×4로만 본다). 테스터가 개발자 본인 1명이라 일반화에 한계 — 판정은 "다음 단계(Godot)로 갈 가치가 있는가" 수준으로만 쓴다.

### D-026. 방어 유닛 제한 이동 (목줄 있는 출격)
- **결정:** 방어 유닛은 방어선 위 `defenseInterceptRange`까지 나가 걱정을 맞받아 막고, 할 일이 없으면 자기 슬롯으로 돌아온다. 유닛마다 다른 걱정을 고르도록 해 한곳에 몰리지 않게 한다. 걱정은 x 최근접 유닛의 y에서 멈춘다. 값은 기본 0으로 구현한 뒤 시뮬 스윕으로 정한다. 타격 이펙트를 함께 넣는다.
- **이유:** 고정 슬롯 + 공격 연출 없음이라 방어 쪽이 정적이다. 유닛에 체력이 있으므로 "앞으로 나가 맞붙는다 → 먼저 맞고 쓰러질 수 있다"가 위험과 판단을 만든다. 심연 유닛은 이미 전진하므로, 위도 움직이되 **목줄**로 "지킨다"(D-013)와 "내려가 뚫는다"의 대비를 유지한다.
- **대가:** 공용 레인 코드 변경 + 밸런스 재조정 (M6.5 결말 분포가 다시 움직인다). 사람 플레이 테스트가 그만큼 늦어진다.
- **버린 대안:** 연출만(규칙 변경 없음 — 비용은 가장 작지만 "체력이 있는 유닛이 나가서 막는" 판단이 생기지 않는다), 자유 사냥(방어선이 사라져 가라앉음 판정부터 재설계, 위/아래 대비 약화).

### D-027. 하루 = 낮(디펜스) → 밤(오펜스), 가로 진행 레인
- **결정:** 두 레인을 동시에 돌리지 않는다. 해가 뜨고 질 때까지 Happy가 걱정을 막고(낮), 달이 뜨고 질 때까지 Unhappy가 꿈속 심연으로 내려가 정화한다(밤). 낮에 손거울에 놓은 조각은 **밤까지 맡겨두고**, 해질녘에 함께 내려간다. 밤에는 창문이 닫힌다. Unhappy 멈춤(그림자 증가)은 밤에만. 화면은 **가로로 진행하는 레인 하나 + 하늘 띠(해/달 궤적)**: 우리 편은 왼쪽, 걱정은 오른쪽에서 밀려오고, 밤에는 왼쪽에서 오른쪽 그림자 벽으로 전진한다.
- **이유:**
  - 테마: 낮 = 의식(양·해·창문), 밤 = 무의식(음·달·손거울). "낮에 겪은 걱정을 잠든 사이 꿈에서 정화한다"가 설명 없이 규칙으로 전달된다. 낮에 가라앉은 걱정이 그날 밤 벽을 단단하게 만들어 인과가 하루 안에서 닫힌다.
  - 폰 화면: 두 레인 + 그리드를 동시에 보는 부담 제거, 레인 폭 176 → 360.
  - 하루 길이: 낮 약 110초 + 밤 60초 → 3~5분 목표에 접근.
  - 맡기기: 순차 구조에서도 낮 내내 "지금 방어에 쓸까 / 밤을 위해 맡길까"가 남아 핵심 선택(H1, D-010)과 "외면하면 역류"(D-001)를 유지.
  - 가로 레인: 해/달이 뜨고 지는 연출과 "밀려옴 / 전진"이 같은 축에서 방향만 반대가 되어 거울 반사 구조(D-010)가 시간축으로 옮겨간다. core 좌표는 그대로 두고 화면 변환만 바꿔 비용을 줄인다.
- **순서(낮 → 밤)를 고른 이유:** 반대(낮 오펜스 / 밤 디펜스)는 루프는 성립하지만 Happy=해·Unhappy=달 상징이 뒤집히고, "밤에 몰려오는 걱정"이 불안한 장면이 되어 동화 톤(D-004)과 충돌하며, 매일이 낯선 모드로 시작한다.
- **D-010 수정:** "합친 조각을 위/아래로 보내 소환, 전투는 양쪽 동시 자동" → "낮에는 창문(즉시)/손거울(맡기기), 밤에는 손거울(즉시)". 조작 체계 1개·레인 코드 공유 원칙은 유지.
- **대가:** M3~M6.5 밸런스·봇 정책·결말 기준 점수 재조정, 레이아웃·View 재작성. 사람 플레이 테스트는 M8.5 이후로 연기. 성장 루프(아래 → 단계 +1 → 위)가 하루 한 바퀴로 느려진다 — 사람 플레이에서 체감 확인.
- **D-026과의 관계:** 방어 유닛 제한 이동은 낮 단계에 그대로 적용하되 레인이 넓어져 수치를 다시 잡으므로 M8.5에서 튜닝과 함께 진행.
- **버린 대안:** 동시 진행 유지 + 시간대 연출만(테마가 규칙에 들어가지 않음), 아래로 보내기는 밤에만(선택이 "남길까 쓸까"로 바뀌고 낮에 외면할 기회가 없어 역설이 약해짐), 세로 진행 유지(해/달 연출과 레인 방향이 따로 놀음).

### D-028. 봇은 밤에 영웅을 남긴다 + 영웅 정화 경고 (→ D-029로 대체)
- **결정:** `balanced` 봇은 밤(그리고 낮의 맡기기)에 영웅을 손거울로 보내지 않는다. 사람에게는 영웅을 손거울에 올릴 때 "정화되면 와일드카드로 돌아와요"를 보여준다. 영웅 귀환 규칙(3단계 정화 → 와일드카드)은 바꾸지 않는다.
- **이유 (M8 시뮬):** 낮/밤 구조에서는 해질녘에 방어 유닛이 그리드로 돌아오고, 밤에는 방어가 쉬므로 "전부 내려보내기"가 자연스럽다. 그런데 영웅이 정화되면 와일드카드가 되어 다음 날 주력이 사라진다 → balanced 가라앉음 398·역류 17. 밤에 영웅만 남기면 가라앉음 101·역류 2·층 돌파 13 (시드 60). 봇이 빠진 함정에 사람도 빠질 가능성이 높으므로, 숨은 함정이 아니라 보이는 선택(도감 진척 vs 방어 유지)으로 만든다.
- **버린 대안:** 영웅이 정화되면 영웅 그대로 + 와일드카드 보너스(밤에 영웅을 보내지 않을 이유가 사라져 밤의 선택이 더 약해짐 — 사람 플레이 후 재검토), 밤에 손거울 정원 축소(맡기기와 겹쳐 복잡).

### D-029. 영웅은 죽지 않고 다친다 · 정화하면 빛난다 · 조합표 · 10층 보스
- **결정:**
  1. 영웅(3단계)·전설(4단계)은 HP 0이 되면 사라지지 않고 **부상**으로 그리드에 돌아와 쉰다. 낮에 다치면 그날 밤까지, 밤에 다치면 다음 날 낮까지 출전 불가 (밤 부상의 그림자 대가는 유지). 1~2단계는 기존대로 쓰러지면 사라진다. 쉬는 영웅도 조합 재료로는 쓸 수 있다.
  2. **정화는 유지**한다. 영웅이 층 돌파에 참여하면 **빛나는 영웅**(능력치 ×1.2)으로 돌아온다. 와일드카드화는 폐지.
  3. **조합표**(원랜디·나랜디식): 빛나는 영웅 + 정해진 재료 → **전설 추억**. 프로토타입은 3개. 조합 도감 화면에서 처음부터 전부 보여준다. 전설은 정화해도 그대로 + 도감.
  4. 와일드카드는 **10층마다 오는 보스 층**(HP ×2, 반격 ×1.5)을 돌파하면 1개.
- **이유:** M8에서 영웅 정화 → 와일드카드가 "밤에 영웅을 보내면 손해"인 함정이었다 (D-028은 임시방편). 영웅은 강아지 같은 소중한 추억이라 죽음은 동화 톤(D-004)·이별 소재 원칙(D-011)과 어긋난다. 부상은 낮/밤 구조(D-027)에서 "낮에 앞세울까, 밤을 위해 아낄까"라는 새 선택을 만든다. 조합표는 쌓이는 영웅의 출구이자 수집 목표(H5)이고, "작은 추억이 합쳐져 큰 추억이 된다"는 머지의 의미를 체인 사이로 넓힌다. 10층 보스는 한 일생(약 11층)의 클라이맥스가 된다.
- **대가:** 영웅을 영구히 잃지 않아 난이도 하락 → M8.6 (b)에서 재튜닝. 와일드카드 공급이 일생당 약 1개로 줄어 그리드 막힘 해소는 놓아주기 중심 (사람 플레이 트랙 B에서 확인). 체인 2개라 조합은 3개뿐 — 동기 검증용이고 본 개발에서 확장. 저장 스키마 변경.
- **D-028 정리:** 영웅 경고 말풍선 제거, 봇 규칙은 "빛나지 않은 영웅을 밤에 정화 + 가능하면 조합"으로 교체.
- **버린 대안:** 정화 선택지 자체를 없애기(밤의 정체성이 사라짐), 영웅도 기존처럼 죽음(톤 충돌·투자 손실), 층 돌파마다 와일드카드(공급 과다로 그리드 압박이 사라짐 — 사용자 결정으로 10층 보스 보상으로), 다친 영웅은 조합에도 못 씀(판단 여지가 줄어듦).

### D-030. 자라는 날 — 전설은 모두 양분이 되고, 결말은 "얼마나 많은 추억을 줬는가"로
- **결정:**
  1. 5일·10일 아침과 일생 끝에 아이가 자란다. 그때 그리드의 **전설 추억은 전부** 양분이 되어 사라지고, 아이 안에 **특성**(해당 체인 유닛 영구 강화)과 **성장치**로 남는다. 영웅과 1~2단계는 남는다. 자랄 때마다 걱정도 강해진다.
  2. 전설은 **행복한 추억**(빛나지 않은 영웅으로 조합)과 **정화된 추억**(빛나는 영웅으로 조합) 두 종류. 행복 1 + 정화 1이 짝지어지면 **기억**이 되어 앨범에 남고 보너스.
  3. 결말은 **양분으로 준 전설의 총량 + 두 종류의 비율 + 갈래**로 판정한다. 두 종류는 같은 무게("모든 기억은 소중하다"). 히든은 세 번 모두 함께 키우고 기억을 일정 수 이상 만든 경우. 처치 수 등 플레이 결과는 결말에 직접 넣지 않는다.
  4. 전설이 없어도 자라기는 일어난다 ("천천히 자란" 갈래). 진행은 막히지 않는다. UI에서 "환생"이라는 말은 쓰지 않는다.
- **이유:** M8.6에서 영웅 불사 + 전설 누적(일생당 22개)으로 힘이 쌓이기만 해 balanced 가라앉음 0·히든 0%. 걱정만 세게 하면 눈덩이를 굴린 쪽은 여전히 쉽고 사람의 초반만 어려워진다 → **주기적으로 힘을 되돌리는 소진**이 필요(프레스티지 리듬). "어린 시절 추억이 자라면서 양분으로 쌓인다"는 세계관을 규칙으로 만들고, 결말을 "어떻게 키웠느냐"(D-005)에 맞춘다. 사라지는 대신 특성으로 남아 손해가 아니라 투자로 느껴지게 한다.
- **대가:** 결말 판정 전면 교체(§5.6 폐지), 튜닝 재수행. 분기점 직전에 전설을 몰아 만드는 플레이가 지배적일 수 있음 → 사람 플레이에서 확인.
- **버린 대안:** 기억을 그리드에서 조합해 앨범으로 보내기(유닛을 그냥 잃는 느낌), 전설 일생 1회 제한(추억은 여러 개여야 함), 분기점에서 전설을 골라 내기(전부 소진이 리듬이 분명하고 고르기 피로가 없음), 진행 차단 게이트(14일 일생·매일 구조와 충돌), "아픈 추억" 명칭(정화된 추억으로 — 모든 기억은 소중하다).
- **이 결정 이후 프로토타입의 큰 구조 변경은 멈춘다.** 튜닝 → 에셋(M9) → 사람 플레이.

### D-031. 소재 기준: 현대사는 다루지 않는다
- **결정:** 현대사·실제 역사적 사건은 사건으로도 배경 암시로도 쓰지 않는다. 개인의 무거운 일(이별·이사·가족의 아픔 등)은 다루되, 걱정을 실제 사람·집단의 상징으로 만들지 않고, 무거운 일을 적·난이도·점수로 만들지 않으며(이정표·그림일기에서 다룸), 정화는 "안아줌"으로 표현한다. 상세는 `docs/01-planning/content-guidelines.md`.
- **이유:** 귀여운 표현은 무거운 감정을 보듬는 힘이 있지만(Spiritfarer·Gris·이별 그림책), 실제 피해자가 있는 집단의 비극을 "막으면 기쁨 +"로 만들면 고통을 소비하는 구조가 된다. 현대사는 해석 논쟁이 크고, 1인 개발이 감당할 리스크가 아니며, 해외 시장(영어 로고·말장난, D-008)에서 맥락이 전달되지 않는다. "평범한 하루도 소중하다"는 메시지는 개인의 일상으로 충분히 전달된다.
- **버린 대안:** 세대마다 다른 시대(현대사) 배경, 무거운 사건을 귀여운 걱정 몬스터로 직접 표현.
- **검토 중 (미결정으로 이동):** 퍼블릭 도메인 설화 중심 구조(중심 설화 후보 "해와 달이 된 오누이", 밤 = 잠자리 동화), 결말 → 다음 아이의 부모가 되는 세대 대물림(재방문 동기). 둘 다 본 개발 설계 대상, 프로토타입 범위 아님.

### D-032. 심연 10층 = 동화 한 편, 한국 설화부터
- **결정:** 밤의 심연을 **동화(설화) 한 편 = 10층**으로 구성한다. 층 = 이야기의 장면, 10층 보스 = 그 이야기의 두려움(정화해서 안아준다). 1~10층은 **"해와 달이 된 오누이"**. 우선 **한국 설화(퍼블릭 도메인)**만 쓴다. 11층 이후 이야기는 미정(후보: 콩쥐팥쥐, 팥죽 할멈과 호랑이, 선녀와 나무꾼, 흥부와 놀부, 별주부전).
- **이유:** 작가가 쓸 재료가 생기고, 이야기 추가 = 업데이트라 끝없이 이어지는 구조(재방문)의 바탕이 된다. 10층 보스(D-029)·밤 = 잠자리 이야기와 그대로 맞물리고, 해 = Happy·달 = Unhappy와 "해와 달이 된 오누이"가 겹친다. 한국 설화만 쓰면 디즈니 각색 저작권·디자인 리스크가 없다.
- **원칙:** 원전만 참고해 직접 다시 쓴다. 잔혹한 대목은 상징으로, 사람 악역(계모 등)은 아이 안의 감정으로 바꾼다 (D-031).
- **보류:** "일생 완결형 vs 이야기 연속형", 자라기(D-030)를 이야기 끝으로 옮길지는 사람 플레이 후 결정. 프로토타입 규칙은 그대로 (14일 일생 ≈ 첫 이야기 + 다음 이야기 입구, 층 이름·보스 이름만 이야기에 맞춤 — M9 에셋 때).
- **버린 대안:** 해외 동화(백설공주·신데렐라) 우선 — 디즈니 버전 인지도 때문에 원전으로 써도 비교·저작권 시비 위험, 해외판 확장 때 검토.

### D-033. 그림일기 → 그림동화, 10층 보스 = 동화책 한 챕터 완성
- **결정 (방향):**
  1. 하루 끝 기록을 **그림동화**로 바꾼다. 하루마다 그날 밤 이야기의 한 장면 페이지가 쓰이고, 그 페이지에 **그날 아이가 겪은 일 한 줄이 이야기 속에 비친다** ("넘어져 무릎을 다친 날, 이야기 속 오누이도 넘어졌다…"). 일상(평범한 하루도 소중하다)은 버리지 않고 이야기 안에 담는다.
  2. **10층 보스를 정화할 때마다 동화책 한 챕터(이야기 한 편)가 완성**된다. 완성된 챕터는 책장에 꽂혀 언제든 다시 읽을 수 있다 → 스테이지를 깨는 의미 = 이야기를 완성하는 것.
  3. (제안) 챕터 완성 순간을 **자라기(D-030)**와 묶는다: 그때까지 만든 전설 추억이 그 챕터의 **삽화·등장인물로 책에 남는다** (사라지는 게 아니라 책 속에 산다) + 특성.
- **이유:** 층 돌파가 숫자가 아니라 "내 이야기책이 채워지는 것"이 되어 수집·재방문 동기가 생긴다. 전설 소진의 상실감(D-030 대가)을 "책 속에 남는다"로 바꾼다. 그림일기의 일상 기록은 페이지 안의 한 줄로 유지.
- **적용 범위:** 프로토타입은 이름·화면 문구·챕터 완성 연출만 (M9 에셋 때). 자라기 시점을 고정 일차(5·10일)에서 **10층 보스 정화 시점**으로 옮길지는 M8.7 (a) 구현 후 시뮬로 비교해 결정 (balanced 기준 한 일생에 보스 층 약 1회라 자라기 횟수가 줄어든다).
- **버린 대안:** 그림일기를 그대로 두고 동화는 밤에만(하루 기록과 이야기가 따로 놀음), 그림일기를 없애고 이야기만(아이의 일상이 사라져 D-005·"평범한 하루" 메시지 약화).

### D-034. 제품 방향: A (이야기 연속 + 결말), 방치형은 넣지 않는다
- **결정:** 방향 A를 유지한다 — 머지는 직접 조작·전투는 자동(D-010), 낮/밤(D-027), 밤 = 동화 속(D-032), 10층 보스 = 동화책 한 챕터(D-033), 자라기·결말(D-030). **오프라인 방치 진행은 넣지 않는다** (D-014 유지).
- **이유:** 방향 B(스톤에이지 키우기식 방치 성장 RPG)는 재방문 동기가 강하지만, 머지 그리드의 역할이 흐려지고, 정체성("어떤 어른이 되는가"·낮/밤 역설)이 "동화 스킨 방치 RPG"로 약해지며, 장르 관행상 성장 가속 판매로 기울어 BM 원칙(성장을 돈으로 팔지 않음)과 충돌한다. 1인 개발로는 장기 수치 운영 부담도 크다. 사실상 새 프로토타입이 필요하다.
- **A 안에서 검토할 것 (사람 플레이 후):** 동화를 완성하면 그 동화의 전설 1개 보상 + 전설 강화 + 보관 기능 — 자라기 소진(D-030)·조합표(D-029)와 공존하는 방식으로 재설계. 한 동화 길이(10스테이지 + 1-5 전환점 제안, "챕터-스테이지" 표기 1-1~1-10).
- **버린 대안:** B 방치형 성장 RPG (위 이유).

### D-035. 한 권의 동화책 = 10챕터 × 10스테이지, 다 채우면 아이가 어른이 된다
- **결정 (본 개발 구조):** 챕터 = 설화 한 편, **1-1 ~ 1-10** (1-5 전환점, 1-10 보스 = 챕터 완성). **10챕터(100스테이지)를 모두 완성하면 동화책 한 권이 완성되고 결말**을 본다. 챕터 완성마다 아이가 한 뼘 자라고(자라기, D-030), 마지막 챕터 완성 = 어른이 되는 결말.
- **이유:** 진행·성장·결말이 하나로 묶인다 (책이 채워짐 = 아이가 자람 = 어떤 어른이 됨). 길이는 balanced 기준 챕터당 약 2주 → 한 권 약 20주(약 140 게임일)로, 기존 목표 "한 회차 약 120일"(세계관)과 비슷하다.
- **대가·주의:**
  - 콘텐츠 분량: 설화 10편 × 장면 10개 = 그림동화 100페이지 + 보스 10 + 전설 10. 1인 개발로 크다 → **출시 1.0은 3~5챕터로 열고 나머지는 업데이트**로 채우는 방식 검토 (그동안 "끝"은 뒤로 밀린다).
  - "끝나면 안 들어온다" 문제는 남는다 → 결말 후 **다음 아이(세대 대물림)로 새 책** 또는 다른 결말 수집 회차 (미결정, 사람 플레이 후).
- **프로토타입:** 규칙은 그대로 (14일 ≈ 1챕터 + 2챕터 입구). 표기·연출만 M9에서.

### D-036. 틀: 어른이 된 내가 다시 펼친 동화책 (아이의 성장 → 어른의 회고)
- **결정:** 플레이어는 **어른이 된 "나"**. 어린 시절 읽던 동화책을 다시 펼치면, 이야기마다 **해의 면(밝은 면, Happy)**과 **달의 면(어두운 면, Unhappy)**이 있다. 낮 = 이야기의 해의 면을 지킨다, 밤 = 이야기의 달의 면으로 내려가 안아준다. 하루 끝 그림동화 페이지에는 **어른인 나의 오늘 한 줄**이 이야기에 비친다 ("회사에서 혼난 날, 이야기 속 오누이도 호랑이를 만났다"). 낮의 걱정은 **어른의 오늘 걱정**(발표, 마감, 월요일 아침…)이 그 챕터 동화의 옷을 입은 모습.
- **바뀌는 해석 (규칙은 그대로):** 추억 조각 → 동화책에서 떠오르는 기억 조각 / 자라기(아이가 자람) → **챕터를 덮을 때 마음에 남는 것**(전설 → 양분 → 특성) / "어떤 어른이 되는가"(D-005) → **"이 책을 다시 덮을 때 나는 어떤 사람인가"**, 마지막 마무리 문장(안) "꿈과 희망을 다시 품은 사람".
- **이유:** 아이 + 성장 + 동화 + 귀여운 그림이 겹치면 첫인상이 아동용(세계관의 "성인 대상" 목표와 충돌). 주인을 어른으로 바꾸면 기억이라는 주제는 지키면서 성인 향수(어린 시절 동화)와 공감(어른의 하루)이 생긴다. "모든 기억은 소중하다"가 어른의 회고가 된다.
- **영향:** D-005("아이가 어떤 어른이 되는가")의 주인을 아이 → 어른인 나로 바꾼다. 결말 5종은 "다시 책을 덮는 나는 어떤 사람인가"의 변주로 다시 쓴다(미결정). 소재 기준(D-031)은 어른의 하루에도 그대로. 아동용 인상은 그림체·스토어 설명에서도 정해지므로 M9 에셋 기준 = "귀엽지만 유치하지 않은".
- **버린 대안:** 동화책 자체가 주인공(정서적 깊이·차별점 약함), 아이 유지 + 어른을 위한 글쓰기(첫인상 리스크 그대로).

### D-037. 결말은 하나: 동화책의 완성
- **결정:** 결말 5종(D-006)을 없앤다. **10챕터를 모두 완성하면 동화책 한 권이 완성되는 것**이 결말이다. 좋은/나쁜 결말, 히든 결말은 없다.
- **유지되는 것:** 행복한 추억/정화된 추억, 자라기(챕터를 덮을 때 전설 → 양분 → 특성), 기억(짝). 이것들은 결말을 가르는 점수가 아니라 **플레이 중의 강화와 기록**이다. (선택) 무엇을 많이 줬는지에 따라 **책의 마지막 삽화·표지만 달라지는** 정도의 변주 — 순위 없이.
- **이유:** "모든 기억은 소중하다"·어른의 회고(D-036)와 맞고, 따뜻한 톤에서 "나쁜 결말"이 주는 불쾌감이 없다. 진행 = 책이 채워짐 = 결말로 구조가 단순해진다.
- **대가:** 결말 수집에 의한 회차 동기가 사라진다 → 재방문은 책 완성 진행·도감·(이후) 다음 책. 난이도의 표현(D-020 "첫 회차에 최선의 결말이 쉽게 나오지 않음")은 **진행 속도**(얼마나 빨리 다음 챕터로 가는가, 가라앉음·역류)로 옮긴다.
- **프로토타입·튜닝 영향:** §5.14-3 결말 판정(총량·비율·갈래)과 §8.2 M6 결말 분포 목표는 폐지 대상. M8.7 (b) 튜닝 목표를 **진행·긴장 지표**로 바꾼다 (예: balanced가 14일 안에 1-10 보스를 정화하는 비율, 중반 가라앉음·역류가 0이 아닌 정도, alwaysHappy·random은 1-10 미도달).
- **버린 대안:** 결말 5종 유지, 공통 마무리 + 5종 변주.

### D-038. 틀 단순화: 해와 달이 동화 속으로 들어가 이야기를 지킨다 (교훈은 동화로)
- **결정:** Happy(해)·Unhappy(달)가 **동화 속으로 들어가** 이야기를 헤쳐 나간다. 낮 = 이야기의 밝은 장면을 **그 이야기의 악당이 보낸 무리**로부터 지킨다, 밤 = 이야기의 어두운 곳으로 내려가 두려움을 정화(안아줌)한다. 머지 조각은 **그 동화의 물건·동료**(챕터마다 체인이 바뀜). 하루마다 "어른의 오늘 한 줄"·현실 걱정은 뺀다. "어른이 다시 펼친 동화책"(D-036)은 **프롤로그·책 표지**로만 남긴다. 주제는 각 동화가 주는 **교훈**과 "모든 이야기엔 밝은 면과 어두운 면이 있고, 둘 다 품어야 이야기가 완성된다".
- **신화 소재 배치:** 사신수 = 해의 면 수호자(전설 동료 후보), 사흉수 = 달의 면 깊은 두려움(일부 챕터 1-10 보스 후보, 잔혹함은 빼고 안아줄 두려움으로), 12지신 = **팀이 아니라 챕터마다 한 마리씩 길잡이**(꾸러기 수비대와 겹치지 않게). 모두 전통 개념이라 자유롭게 쓸 수 있다.
- **이유:** 현실(어른의 하루)과 동화를 겹치면 "낮의 걱정 / 밤의 걱정"이 애매해진다. 동화 속 모험 하나로 묶으면 즉시 이해되고, 챕터마다 새 동료·적·배경이 생긴다.
- **대가 (수용):** "평범한 하루도 소중하다"·기억이라는 정서적 주제가 거의 사라진다 → 동화의 교훈과 두 면의 주제로 대신한다. 장르 내 차별점은 해/달·낮/밤 역설·정화(안아줌)·한국 설화로 지킨다. 교훈은 설교하지 않고 플레이로 보여준다.
- **영향:** D-036의 "어른의 하루 한 줄"·"낮 걱정 = 어른의 걱정" 철회. 그림동화(D-033) 페이지 = 그날 헤쳐 나간 장면만. 규칙 변경 없음 — 이름·그림·문구는 M9. 1챕터 초안: `01-planning/stories/ch01-sun-and-moon.md`.

### D-039. 우리가 동화책을 여행한다 + 동화 틀에 맞춘 규칙 정리 4가지
- **결정:**
  1. **주체:** 해와 달이 들어가는 게 아니라 **우리(플레이어)가 동화책을 여행**한다. 해(Happy)와 달(Unhappy)은 그 여행의 **두 길동무** — 낮에는 해가 이야기의 밝은 장면을 함께 지키고, 밤에는 달이 어두운 곳으로 길을 밝힌다. (D-038의 "해와 달이 동화 속으로 들어간다"를 대체)
  2. **이벤트·이정표:** 아이의 일상 이벤트(넘어진 날·생일·이 뽑는 날)는 **그날의 이야기 장면 효과**로 바꾼다 (예: "비 내리는 고갯길" = 걱정 강화, "떡 찌는 냄새" = 조각 지급). 이정표는 **동화 속 갈림길 선택**으로 (예: 1-5 "문을 열어줄까 — 해가 맡음 / 열지 말까 — 달이 맡음"). 기존 효과 규칙(기쁨·그림자·face 보너스)은 그대로, 이름·문구만 교체.
  3. **자라기 시점:** 고정 일차(5·10일) → **1-5 전환점 정화와 1-10 보스 정화 때** (챕터당 2번). 일생 끝 자동 자라기는 폐지.
  4. **프로토타입 한 판의 끝:** 14일 → **1-10 보스 정화 = 1챕터 완성 = 끝**. 정화 못 하면 `maxDays`(20)일째에 "아직 이야기가 남았어요"로 마무리.
  5. **M9 에셋:** 기존 무료 팩(Cute Fantasy RPG·Sprout Lands, 서양 판타지·농장풍)으로 진행하고 색·소품만 최대한 맞춘다. 본 개발 아트는 **동양 설화풍**(특정 나라에 묶지 않음)으로 — 단, 한국 설화 챕터에 다른 나라의 상징적 요소(특정 건축·의복 양식)를 섞지 않는다 (문화 혼동 논란 방지). 이후 중국·일본 설화 챕터를 넣을 때는 그 이야기에 맞는 풍.
- **이유:** 2~4는 D-037(결말 = 책 완성)·D-038(현실 하루 제거)과 기존 구현 사이의 어긋남을 정리. 자라기를 1-10에서만 하면 14일에 1번쯤이라 힘을 되돌리는 효과가 약하다. 5는 프로토타입 목적이 재미 확인이라 분위기 완성은 뒤로.
- **구현:** 2·3·4는 규칙 변경 → **M8.8** (M8.7 (a) 커밋 후, 스펙 §5.15). 결말 5종 판정 코드(§5.14-3)는 M8.8에서 "챕터 완성" 하나로 단순화. 이후 M8.7 (b) 튜닝은 M8.8 기준으로.

### D-040. 동화 → 설화(옛이야기) 여행, 책 한 권 = 한 문화권
- **결정:** 개념을 "동화책 여행"에서 **"설화 여행"**으로 바꾼다. 화면 용어는 **"옛이야기"** (문서·기획은 "설화"). 그림책 형식(한 장씩 넘김, 챕터가 책에 꽂힘)은 유지. 결말 = **옛이야기 책 한 권 완성**.
- **확장 구조:** **책 한 권 = 한 문화권의 설화·신화 10챕터.** 1권 = 동양 설화(해와 달이 된 오누이, 12지신 길잡이, 사신수·사흉수), 이후 권 후보 = 그리스·로마 신화, 북유럽 신화, 이집트 신화 등. 한 권을 다 채우면 **다음 책**이 열린다 → 책 완성 이후 재방문 문제(D-035·D-037 대가)의 해답.
- **이유:** "설화"는 신화·전설·민담을 다 아우르므로 지금 재료(민담·민속·신화 동물)가 한 틀에 들어가고, "동화"보다 아동용 인상이 약하며, 세계 신화로 넓힐 때도 어색하지 않다.
- **주의:**
  - 원전(퍼블릭 도메인)만 참고. **현대 각색물의 해석·디자인**(마블의 토르·로키, 특정 영화·게임의 신 디자인)은 쓰지 않는다.
  - **지금도 믿는 종교의 신**은 다루지 않거나 극히 조심한다 (예: 힌두교 신들). 그리스·북유럽·이집트처럼 고대 신앙 신화 위주.
  - 그리스·북유럽·이집트 신화는 이미 많은 게임이 쓴 소재 → 차별점은 낮/밤(해의 면·달의 면)·정화(안아줌)·그림책 형식.
  - 해외판 화면 용어는 "Tales"/"Old Tales" 등 별도.
- **영향:** 용어 교체만 (규칙 변경 없음). D-032의 "우선 한국 설화만"은 "1권은 동양 설화"로 넓힌다.

### D-041. 권 순서가 곧 난이도: 1권 설화 → 2권 동양 신화 → 세계 신화
- **결정:** 모드(이지/하드)로 콘텐츠를 나누지 않고 **책 순서 자체를 난이도 곡선**으로 한다. 1권 = 설화(민담, 쉬움, 규칙을 익히는 책), 2권 = 동양 신화(사신수 = 수호자, 사흉수 = 보스, 보통), 3권 이후 = 그리스·로마·북유럽·이집트 신화(점점 어려움). 사신수·사흉수는 1권에서 2권으로 옮긴다.
- **이유:** 이지 = 설화 / 하드 = 신화로 나누면 하드를 안 하는 유저는 신화 콘텐츠를 못 보고(1인 개발 콘텐츠 낭비), 모드별 콘텐츠를 따로 만들어야 하며, "하드" 장벽이 따뜻한 톤과 맞지 않는다. 순서로 하면 모든 유저가 모든 이야기를 만나고, 이야기 규모(마을 → 하늘 → 세계의 신)가 플레이어 성장과 함께 커진다.
- **나중에 (본 개발):** 책을 다 읽은 사람용 **"다시 읽기(어려움)"** — 같은 책을 높은 수치로. 새 콘텐츠 없이 재방문 동기.
- **보류:** 길잡이(12지신 등)를 어떻게 쓸지는 다시 고민 (D-038의 "챕터마다 12지신 한 마리" 안은 후보로만 둔다).

### D-042. 1-10 보스를 정화하면 두 동료: 해의 동료(주인공) + 달의 동료(정화된 악당) (→ D-043으로 수정)
- **결정 (방향):** 챕터를 완성하면 그 이야기의 **해의 동료**(예: 해와 달이 된 오누이)와 **달의 동료**(예: 정화된 호랑이)를 얻는다. 해의 동료는 낮 레인에서, 달의 동료는 밤 레인에서 함께 싸운다. 조합 전설(소모, 자라기에 양분)과 달리 **영구 동료** — 다음 챕터·다음 책으로 이어지고 강화할 수 있다.
- **이유:** 낮/밤 구조와 정확히 맞는다 (밝은 면의 주인공 + 안아준 어두운 면). "정화한 두려움이 동료가 된다"는 정화(안아줌)의 의미를 보상으로 보여준다. 미결정이던 "권 사이에 이어지는 것"·"전설 보상·강화·보관"의 답이 된다.
- **주의:** 10챕터 × 2 = 한 권에 동료 20명 → 강하면 다음 챕터가 쉬워진다. 약하게 시작해 강화로 키우고, **낮·밤 각각 출전 슬롯을 제한**(예: 1~2명)해 고르게 하는 편성 레이어가 필요할 수 있다 (D-010에서 보류했던 "덱 편성"이 장기 레이어로 자연스럽게 들어옴).
- **프로토타입:** 판이 1-10에서 끝나므로 챕터 완성 화면에 두 동료 카드 표시만 (§5.15-5). 동료 효과·강화·편성은 본 개발.
- **조합표는 유지한다** (2026-10-01): 계속 소환하고 머지하는 재미의 핵심이므로 덱 편성으로 대체하지 않는다. 덱·시너지(삼국지 전략판·스톤에이지 키우기식 4인 팀)는 **동료 편성 레이어**로만 검토 — 판 안의 머지·조합(소모) / 판 밖의 동료 팀(영구)으로 층을 나눈다.
- **판 안 → 판 밖 연결 (방향, 2026-10-01):** 덱 = 그리드에 나올 체인을 가져오는 동료 4명 팀(랜덤다이스식). 판 안에서 머지·조합으로 만든 전설은 자라기(1-5·1-10)에 양분으로 소진될 때 **그 체인을 가져온 동료의 강화 재료**가 된다 (지금의 "특성"이 본 개발에서는 동료 강화로). 조합표는 덱에 든 체인 조합에 따라 달라져 덱 시너지가 된다.

### D-043. 보스 보상 = 그 이야기 주인공의 조합법 (D-042 수정), 체인은 책마다 4~6개
- **결정:** 1-10 보스를 정화하면 **해의 조합법 1개 + 달의 조합법 1개**를 얻는다. 결과물이 그 이야기의 주인공 전설 (1챕터: "해와 달이 된 오누이" / "정화된 호랑이"). 완성된 유닛을 주지 않는다. **체인은 책마다 4~6개**(처음 2개, 2~3챕터마다 1개씩 열림), 덱은 그중 4개를 고른다.
- **이유:** 싸우는 것은 머지로 만든 유닛이므로(모델 1) 보상도 머지와 이어져야 한다. 챕터마다 체인 2개씩 주면 한 권 20개·네 권 80개로 1인 개발 아트·밸런스가 감당되지 않는다. 체인(재료)은 적게, 조합법(목표)을 챕터마다 늘리면 같은 체인으로도 매번 노리는 것이 새롭다. 조합표 = 덱 시너지 구조 유지.
- **D-042 수정:** "해의 동료 + 달의 동료(영구 유닛)" → 위 조합법. 판 안 전설이 자라기 때 **그 체인의 강화 재료**가 되는 연결은 유지.
- **프로토타입:** 챕터 완성 화면 문구만 — "오누이와 정화된 호랑이를 만드는 법을 알게 되었다" (§5.15-5).
- **다음:** 체인 구조가 실제로 재미있는지는 플레이로 확인한다 (사용자: "일단 플레이해봐야").
